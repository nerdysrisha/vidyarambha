Manage Microsoft Entra ID Identities AZ-104

Before anything in Azure can be secured, it needs to know who is asking. Microsoft Entra ID is the service that answers that question. This topic covers the identities it holds (users and groups), why they matter, and a short hands-on exercise to build them yourself.

Part 1

The Notes: what these identities are

What is Microsoft Entra ID?

Microsoft Entra ID (formerly Azure Active Directory) is Azure's cloud-based identity and access management service. It authenticates people (proving who they are) and provides the identities that Azure then uses to authorize access (deciding what they may do). Every Azure subscription trusts exactly one Entra ID tenant for this.

Tenant: a dedicated instance of Entra ID that represents your organization. It holds all users, groups and devices. You can have more than one tenant and switch between them, but each identity lives in one.

The goal in one picture

The idea is simple: create identities, collect them into groups, then give access to the group rather than to individual people. This topic builds the first two layers. Granting access (RBAC) comes in a later topic.

The identity types

IdentityWhat it isTypical use
Member userAn account created in (or synced to) your tenant. Signs in with a credential your organization owns.Employees, engineers, administrators
Guest userAn external person invited into your tenant (B2B collaboration). They sign in with their own organization's or personal account.Partners, contractors, consultants
GroupA container of users or devices so access and settings can be applied once.Teams, roles, departments
DeviceA registered or joined computer or phone.Conditional Access, device-based groups
Service principal / managed identityAn identity for an application or Azure resource rather than a person.Apps and VMs calling other Azure services

Groups: type and membership

Two separate choices define a group. The group type says what it is for. The membership type says how people get in.

ChoiceOptionsNotes
Group typeSecurity, Microsoft 365Security groups manage access to resources. Microsoft 365 groups add collaboration features such as a shared mailbox and Teams.
Membership typeAssigned, Dynamic user, Dynamic deviceAssigned is manual. Dynamic is rule based and requires Entra ID P1 or P2. A dynamic group holds users or devices, never both.
OwnersOne or moreOwners can manage a group and its membership without being tenant administrators.

Group settings worth knowing: Expiration sets a lifetime in days after which the owner must renew the group. Naming policy blocks words and adds a prefix or suffix to group names.

Part 2

The Exercise: build it yourself

Scenario: a pre-production environment is being built and new engineers will manage it, including the virtual machines. They must sign in with Entra ID, so you provision their identities and one group to hold them. Estimated time is about 30 minutes in an Azure subscription (steps use East US, but any region works).

Task 1: Create the users

Get oriented

  1. Sign in to the Azure portal at https://portal.azure.com. If the Welcome to Azure splash screen appears, select Cancel.
  2. Search for and select Microsoft Entra ID. Browse the left pane, then open Overview and the Manage tenants tab to see your tenant. Go back to the Entra ID page.
  3. If time allows, look at Licenses and Password reset.

Good to remember for the exam

  • A tenant represents your organization. Users, guests, groups and devices all live inside it.
  • Guests are invited, not created. They use their own credentials and show a user type of Guest.
  • Set usage location before assigning a licence, or the assignment fails.
  • Dynamic membership needs Entra ID P1 or P2, and a dynamic group holds users or devices, not both.
  • Security groups manage access. Microsoft 365 groups add collaboration features.
  • A group that can be assigned Entra roles must use Assigned membership.
Part 3

Test yourself

Try each question first, then press the button to reveal the answers.

  1. What is a Microsoft Entra ID tenant?
    Answer: A dedicated instance of Entra ID that represents your organization and holds its users, groups and devices. An Azure subscription trusts one tenant for identity.
  2. You create a user and try to assign a licence, but it fails. Which property was most likely missing?
    1. Department
    2. Job title
    3. Usage location
    4. Display name
    Answer: C. A usage location is required before a licence can be assigned, because service availability depends on country.
  3. Which statement about guest users is correct?
    1. They are created with an auto-generated password
    2. They are invited and sign in with their own account
    3. They cannot be added to groups
    4. They must be in the same tenant as the admin
    Answer: B. Guests are invited by email (B2B) and authenticate with their own organization's or personal account. They can be added to groups.
  4. A guest has been invited but has not accepted yet. Can you add them to a group?
    Answer: Yes. The guest object exists in your tenant as soon as the invitation is sent, so it can be added to groups straight away.
  5. Which group type is intended to control access to resources, and which adds a shared mailbox and Teams?
    Answer: Security groups manage access. Microsoft 365 groups provide collaboration features such as a shared mailbox, calendar and Teams.
  6. What licence is required to use dynamic membership?
    Answer: Microsoft Entra ID Premium P1 or P2. On a free tenant the membership type drop-down only offers Assigned.
  7. Write a dynamic membership rule that adds every user whose job title is "IT Lab Administrator".
    Answer: (user.jobTitle -eq "IT Lab Administrator")
  8. An engineer moves from the IT Lab Administrator role to another title. What happens to their membership in (a) an assigned group and (b) a dynamic group based on job title?
    Answer: (a) Nothing. They stay a member until an administrator or owner removes them. (b) Entra ID re-evaluates the rule and removes them automatically.
  9. Can a single dynamic group contain both users and devices?
    Answer: No. A dynamic group is either a dynamic user group or a dynamic device group.
  10. What are group Expiration and Naming policy used for?
    Answer: Expiration sets a group lifetime in days after which the owner must renew it, which removes stale groups. Naming policy blocks certain words and adds a prefix or suffix to names so groups stay consistent.
  11. Scenario: new engineers join every month and your manager wants access to follow their job title with no admin effort. Which membership type do you choose, and what must you check first?
    Answer: Dynamic membership with a rule on job title. First confirm the tenant has Entra ID P1 or P2, and that job titles are filled in consistently on the user accounts.
