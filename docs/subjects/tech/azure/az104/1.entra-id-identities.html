Manage Microsoft Entra ID Identities AZ-104

Azure must know who you are before it lets you do anything. Microsoft Entra ID is the service that knows.

Part 1

Notes

Where Entra ID fits in Azure

What is Entra ID?

  • Azure's sign-in and identity service. Old name: Azure Active Directory.
  • A tenant is your organization's own Entra ID space.
  • Entra ID checks who you are. RBAC (later topic) decides what you can do.

The identities

  • Member user: account made inside your tenant. Example: an employee.
  • Guest user: outside person you invite by email. They use their own login.
  • Group: a bundle of users or devices. Give access once, to the group.
  • Device: a registered computer or phone. Can also be in groups.
  • Service principal / managed identity: identity for an app or VM, not a person.

User properties that matter

  • User principal name (UPN): the sign-in name.
  • Job title / department: can decide group membership (dynamic groups).
  • Usage location: must be set before you assign a licence.

Groups

  • Security group: for access to resources. Microsoft 365 group: adds shared mailbox and Teams.
  • Owner: can manage the group's members.
  • A dynamic group holds users or devices, not both.
  • Expiration = owner must renew the group after X days. Naming policy = blocked words, prefix or suffix.
Part 2

Exercise

Goal: create one member, one guest and one group that holds both. Time: about 30 minutes.

Task 1: Users

Azure portal (portal.azure.com) → search Microsoft Entra ID → Users.

  1. Create the member: New user → Create new user.
    • User principal name and display name: az104-user1
    • Auto-generate password and Account enabled: both ticked
    • Properties tab: job title IT Lab Administrator, department IT, usage location United States
    • Review + create → Create
  2. Invite the guest: New user → Invite an external user.
    • Use your own email and name. Tick Send invite message.
    • Message: Welcome to Azure and our group project
    • Properties tab: same job title, department and usage location as above
    • Review + invite → Invite

Check: refresh Users. You see az104-user1 (Member) and your guest (Guest).

Task 2: Group

Microsoft Entra ID → Groups → + New group.

  1. Group type: Security. Name: IT Lab Administrators. Description: Administrators that manage the IT lab. Membership type: Assigned.
  2. No owners selected → pick yourself.
  3. No members selected → pick az104-user1 and your guest.
  4. Create, then refresh.

Dynamic membership only shows in the drop-down if you have Entra ID P1 or P2.

Check: open the group. Members shows 2, Owners shows you.

Good to remember for the exam

  • Guests are invited, not created. They use their own login.
  • Set usage location before assigning a licence.
  • Dynamic membership needs Entra ID P1 or P2.
  • Dynamic group = users or devices, not both.
  • Security group = access. Microsoft 365 group = collaboration.
  • A group that can hold Entra roles must be Assigned, not dynamic.

  1. Your organization's own Entra ID space. It holds users, groups and devices.
  2. C. Usage location is required before licensing.
  3. A guest is invited and signs in with their own account. A member is created in your tenant.
