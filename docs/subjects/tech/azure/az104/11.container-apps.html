Azure Container Apps AZ-104

Azure Container Apps (ACA) runs your containers on a serverless platform. Behind the scenes it uses Kubernetes, but Azure manages the cluster for you. You bring the image, ACA gives you a web address and handles scaling. This topic covers environments, container apps, ingress, revisions, scaling and how ACA compares with ACI and AKS.

What ACA is

  • ACA is a serverless platform for running containers. You do not manage servers, VMs or a Kubernetes cluster.
  • It is built on Kubernetes, but Azure runs the cluster and adds managed extras on top (scaling, ingress, secrets, monitoring).
  • Good for microservices, web apps, APIs and background workers. Workloads are usually long-running, like a web app.
  • Lab scenario: a web app on an on-premises VM moves to the cloud, with no large fleet of servers to look after.
  • You can scale to zero replicas when there is no traffic, so you can save cost.

Environment and container app

Environmentmy-environmentsecure boundary
shared virtual networkshared logs
App 1web front end
App 2orders API

Apps in the same environment can talk to each other and send logs to the same place.

  • A Container Apps environment is the secure boundary around one or more container apps. Apps in it share a virtual network and a Log Analytics workspace.
  • A container app is your running application. It lives inside exactly one environment.
  • In the portal you can pick an existing environment or choose Create new environment (the lab creates my-environment).
  • Plan type: Consumption (pay for what you use, can scale to zero) or Dedicated workload profiles (reserved compute).

Ingress

  • Ingress controls how traffic reaches your app. Turn it on to get a web address (FQDN).
  • External: reachable from the internet. Internal: only reachable from inside the environment or its virtual network.
  • You set the target port, the port the container listens on. The Hello World image uses port 80.
  • Azure gives the app a DNS name, shown as the Application URL on the Overview page.
  • No ingress means the app is not reachable by HTTP. That fits background workers.

Revisions and scaling

Revisionmy-app--abc123snapshot of one version
replica 1replica 2...up to max

A new revision is created when you change the container settings. Scaling adds or removes replicas.

  • A revision is an immutable snapshot of a version of your app. Changing the container or image creates a new one.
  • Revision modes: Single (default, only the latest is active) or Multiple (run several and split traffic, useful for blue-green and testing).
  • A replica is one running copy of a revision.
  • Scale rules decide how many replicas run: HTTP requests, TCP connections, CPU or memory, or custom event sources (KEDA, for example a queue length).
  • You set a minimum and maximum replica count. A minimum of 0 means scale to zero.

Image source

  • Quickstart image: a Microsoft sample. The lab uses Simple hello world container.
  • Untick Use quickstart image to use your own image from Azure Container Registry, Docker Hub or another registry.
  • Other settings on the Container tab: CPU and memory, environment variables, commands.

ACA, ACI, AKS or Web Apps?

Less to manage → more control
ACI (single containers)→ACA (serverless apps)→AKS (full Kubernetes)

A rough guide for the exam. All of them can run containers.

  • ACI: quick single containers or jobs. No built-in scaling or revisions.
  • ACA: microservices and web apps with autoscaling (even to zero), revisions and ingress, without managing Kubernetes.
  • AKS: you manage the cluster. Choose it when you need full Kubernetes control.
  • App Service: web apps with slots and custom domains. It can also run a container.

Exercise

Goal: create a container app and its environment from a Quickstart image, then open the Application URL to prove it works. About 15 minutes.

1 Create app + environment2 Test and verify

Lab names are kept: az104-rg9, my-app and my-environment. Region is East US, but you may change it.

Task 1: Create and configure an Azure Container App and environment

  1. Portal → search for and select Container Apps.
  2. + Create → Container App (look at the other choices in the menu).
  3. On Basics:
    • Subscription: your subscription
    • Resource group az104-rg9
    • Container app name my-app
    • Region East US
    • Container Apps Environment: Create new environment, name it my-environment, then Create
  4. Next: Container. Make sure Use quickstart image is ticked (scroll up if you cannot see it).
  5. Set Quickstart image to Simple hello world container.
  6. Under Application ingress settings, set the ingress options as needed, then Next: Tags.
  7. Review and create, then Create. Wait a couple of minutes.

Check: the deployment completes without errors.

Task 2: Test and verify deployment of the Azure Container App

  1. Select Go to resource to open my-app.
  2. On Overview, select the link next to Application URL. It opens in a new tab and is served on port 80.
  3. Check that you see the message Your container app is running with a Hello World image.

Check: the Application URL loads and shows the Hello World message.

Cleanup: delete az104-rg9 when you finish (select the resource group, Delete the resource group, type its name, Delete). PowerShell: Remove-AzResourceGroup -Name az104-rg9. CLI: az group delete --name az104-rg9. This also removes other labs' resources in the same group.

Good to remember for the exam

  • ACA = serverless containers on managed Kubernetes. You do not manage the cluster.
  • Hierarchy: environment contains container apps. Apps in one environment share a virtual network and logs.
  • Ingress External = internet, Internal = environment or VNet only. You set the target port.
  • A revision is an immutable version. Multiple revision mode allows traffic splitting.
  • Scale rules: HTTP, TCP, CPU, memory or custom (KEDA). Min replicas 0 = scale to zero (Consumption plan).
  • ACA suits long-running apps (web, API, microservices). ACI suits simple one-off containers. AKS gives full Kubernetes control.
  • The quickstart image is for testing. Use Azure Container Registry for your own images.
  • The Application URL is on the app's Overview page.
