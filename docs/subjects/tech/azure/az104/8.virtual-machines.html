Building Virtual Machines AZ-104

An Azure VM is never just "a server". It is a virtual machine plus a small set of networking and storage resources that sit around it: a virtual network to live in, a network card to connect, disks to boot from, and rules to decide what traffic gets in. Then you choose an image, a size, a security type, where it runs, and how it scales.

Base images

  • An image is the starting point for the OS disk. You pick it on the Basics tab.
  • Marketplace images: ready-made by Microsoft and partners. Windows Server (2019, 2022 and so on), Ubuntu Server, Red Hat, SUSE, Debian and more.
  • Custom images: your own, captured from a configured VM, so every new VM starts with your software already on it.
  • Azure Compute Gallery: a store for your images that lets you version them and share them across regions and subscriptions.
  • Gen1 or Gen2: Gen2 VMs use UEFI boot and are needed for Trusted launch and Confidential VMs. The lab uses Windows Server 2019 Datacenter - x64 Gen2.
  • Windows VMs are reached with a username and password over RDP (port 3389). Linux VMs usually use an SSH key (port 22).
  • Already have a Windows Server license? Tick it to reuse your license (Azure Hybrid Benefit) and pay less. The lab leaves it unticked.

VM sizes

  • The size sets vCPUs, memory, number of disks and network speed. Pick it for the workload.
  • Sizes are grouped into families (see the diagram).
  • Reading a name such as Standard_D2ds_v4: D = family, 2 = vCPUs, s = supports premium SSD, d = has a local temp disk, v4 = hardware version.
  • Resizing a VM to another size is vertical scaling (up or down). It usually restarts the VM, and the new size must be available in that region and hardware cluster.
  • Azure Spot VMs use spare capacity at a big discount, but Azure can take them back (evict them) at any time. Good for work that can be interrupted. The lab leaves Spot unticked.

VM security types

  • Standard: no extra security features. This is what the lab uses.
  • Trusted launch: protects the VM from boot-level attacks (rootkits and bootkits). Gen2 only.
  • Confidential: hardware-based protection that keeps data encrypted even while it is being processed in memory. Even Azure operators cannot see it. Needs special sizes (such as DC and EC series) and Gen2 images.
  • In short: Standard = none, Trusted launch = protects boot, Confidential = protects data in use.

Availability: zones and sets

  • Availability zones: separate datacenters inside one region, each with its own power, cooling and network.
  • 99.99% SLA needs at least two VMs in different zones. Even for one VM it is best practice to choose a zone.
  • In the portal, ticking Zone 1 and Zone 2 creates two VMs, one per zone.
  • Availability set: spreads VMs across fault domains (separate racks) and update domains (staggered maintenance) in one datacenter. SLA 99.95%.
  • A single VM using Premium SSD for all its disks has a 99.9% SLA.

Disks

  • Every VM has an OS disk. You can add data disks. All are managed disks.
  • Disk types: Standard HDD (cheapest, infrequent use), Standard SSD (light workloads), Premium SSD (production), Ultra Disk (highest performance).
  • Delete with VM: when ticked, the disk is deleted when the VM is deleted. The same option exists for the NIC and public IP. This avoids leftover resources that keep costing money.
  • Detach removes a disk from the VM but keeps it, so you can attach it later or to another VM.
  • You can change a disk's type and size in the Disks resource. Change the type while the disk is detached (or the VM is deallocated).
  • Disk encryption: managed disks are encrypted at rest by default (server-side encryption). For more, use encryption at host or Azure Disk Encryption (BitLocker on Windows, DM-Crypt on Linux), with keys held in Key Vault.
  • Snapshot: a read-only point-in-time copy of a disk. Create a new managed disk from it to back up or clone a VM.
  • VHD and images: a managed disk is stored as a VHD behind the scenes. You can upload a VHD to create a disk, and capture a generalized VM as an image to create many identical VMs.

Running, stopped and deallocated

  • Stopping a VM from Azure (portal, Stop-AzVM, az vm deallocate) makes its status deallocated.
  • Deallocated: you stop paying for compute, and a non-static public IP is released. Disks are still billed.
  • Shutting down from inside the OS (for example Windows Shut down) only stops the OS. The VM stays allocated and you keep paying for compute.
  • Redeploy moves the VM to a new Azure host. Use it for connection problems that restarting does not fix. The VM restarts, and data on the temporary disk is lost.
  • Move a VM to another resource group or subscription with Move in the portal. The resource ID changes, but the region stays the same. Moving to another region needs Azure Resource Mover.

Scaling: up and out

  • Vertical scaling (scale up/down): change the size of one VM (resize), or the disk type and size.
  • Horizontal scaling (scale out/in): change the number of VMs. Done with a Virtual Machine Scale Set.

Virtual Machine Scale Sets (VMSS)

  • A scale set is a group of VMs created from the same image and configuration, usually behind a load balancer.
  • The number of instances can grow and shrink automatically, based on demand or a schedule.
  • Orchestration mode: Uniform = identical instances managed as one group (lab). Flexible = more freedom, can mix VM types.
  • Can spread instances across zones (the lab uses Zones 1, 2 and 3).
  • The lab adds an NSG that allows HTTP, and a public load balancer.

Autoscale

  • Manual scale: you set the instance count. Fine for a small number of instances.
  • Custom autoscale: rules react to a metric (such as CPU) or a schedule. Better for many instances.
  • Always make a scale out rule and a matching scale in rule, otherwise you never shrink and keep paying.
  • Duration = the time window the metric is checked over. Cool down = the wait after a scale action before another one is allowed.
  • Instance limits stop runaway scaling: minimum, maximum and default (the count used if metric data is missing).

Connecting and managing

  • The lab sets Public inbound ports: None. No port is open to the Internet. Connect through other means, such as Azure Bastion (RDP or SSH in the portal over TLS, no public IP needed on the VM).
  • Patch orchestration: Azure orchestrated lets Azure apply guest OS patches.
  • Boot diagnostics is disabled in the lab to save cost. Turn it on to see the VM's screen and serial output when troubleshooting.
  • You can create VMs from the portal, Azure PowerShell (New-AzVm) or the Azure CLI (az vm create), both runnable from Cloud Shell.
  • VM extensions are small add-ons that run after deployment, for example monitoring agents. The Custom Script Extension downloads and runs a script on the VM to install software or configure it.
  • An ARM template (JSON) or Bicep file describes the VM and its resources, so you can redeploy the same VM again and again. Use Download a template for automation on the Review + create page, or Export template from an existing VM.
  • Connect with RDP (port 3389, Windows) or SSH (port 22, Linux), directly or through Bastion.

Good to remember for the exam

  • A VM needs at least one NIC, and each NIC sits in exactly one subnet. The VM, NIC and VNet must be in the same region.
  • Azure reserves the first four addresses and the last one in every subnet, which is why the first VM in 172.16.0.0/24 gets 172.16.0.4.
  • NSG rules can apply at the subnet level, the NIC level, or both. When both exist, traffic must be allowed by each of them.
  • A public IP is optional. A VM with no public IP can still reach and be reached by other resources inside the VNet.
  • 99.99% SLA needs two or more VMs in different availability zones. Availability set = 99.95%. One VM with Premium SSD = 99.9%.
  • Security types: Standard (none), Trusted launch (boot protection), Confidential (data in use is encrypted). Trusted launch and Confidential need Gen2.
  • Image = where the OS disk comes from (Marketplace, custom, Compute Gallery). Size = CPU, memory and price.
  • Resize = vertical scaling. Scale set instances = horizontal scaling.
  • Detach keeps the disk. Delete with VM removes the disk (and NIC or public IP if ticked) when the VM is deleted.
  • Stop from Azure = deallocated = no compute billing. Shutdown from inside the OS = still billed.
  • Scale set instances share one image and configuration. Autoscale needs a scale out rule, a scale in rule and min, max and default limits.

Test yourself

Try each question first. Press the button to show every answer under its question.

Check answersHide answers
  1. How do you get the 99.99% uptime SLA for virtual machines?
    Deploy at least two VMs in different availability zones of the same region. In the lab, ticking Zone 1 and Zone 2 creates two VMs, one per zone.
  2. Which VM security type keeps data encrypted while it is being processed in memory?
    1. Standard
    2. Trusted launch
    3. Confidential
    4. Azure Spot
    C. Confidential VMs use hardware-based protection for data in use. Trusted launch protects the boot process (Secure Boot, vTPM, boot integrity monitoring). Standard has no extra features. Spot is a pricing option, not a security type.
  3. What is the difference between an availability zone and an availability set?
    A zone is a separate datacenter in a region (SLA 99.99% with two or more VMs across zones). An availability set spreads VMs across fault domains and update domains inside a datacenter (SLA 99.95%).
  4. Give three places a base image can come from, and one example for Windows and Linux.
    Azure Marketplace, a custom image, and an Azure Compute Gallery. Examples: Windows Server 2019 Datacenter Gen2 (portal and Win2019Datacenter in PowerShell), Ubuntu Server 22.04 (Ubuntu2204 in the CLI).
  5. You change a VM from Standard_D2s_v3 to Standard_D2ds_v4. What kind of scaling is this, and what should you expect?
    Vertical scaling (resize). The VM usually restarts, and the new size must be available in that region and hardware cluster.
  6. Which action is horizontal scaling?
    1. Resizing a VM to a larger SKU
    2. Adding more instances to a scale set
    3. Changing a data disk from HDD to SSD
    4. Adding a data disk to a VM
    B. Horizontal scaling changes the number of VMs. The others are vertical changes to one VM.
  7. What does "deallocated" mean, and what does shutting down from inside Windows do instead?
    Deallocated (stopped from Azure) releases the compute: billing for compute stops and a non-static public IP is released. Disks are still billed. Shutting down from inside the OS leaves the VM allocated, so you keep paying for compute.
  8. What does Detach do to a data disk?
    It removes the disk from the VM but keeps it in storage. You can change its type (the lab changes Standard HDD to Standard SSD) and attach it again, to this VM or another.
  9. What does "Delete with VM" do, and why tick it?
    The disk (and, with the networking option, the NIC and public IP) is deleted automatically when the VM is deleted. It stops leftover resources from sitting there and costing money.
  10. Explain this rule: Percentage CPU, average, greater than 70, 10 minutes, increase percent by 50, cool down 5.
    When the average CPU over a 10-minute window is above 70%, the scale set adds 50% more instances. Then it waits 5 minutes (cool down) before another scale action is allowed.
  11. What are the instance limits minimum 2, maximum 10, default 2 for?
    Minimum: the scale set never scales in below 2 instances. Maximum: it never scales out above 10. Default: the count used when metric data is not available.
  12. What does Uniform orchestration mean for a scale set, and what do its instances share?
    Uniform means all instances are identical and managed as one group. They are created from the same image and configuration. (Flexible orchestration allows more freedom, such as mixing VM types.)
