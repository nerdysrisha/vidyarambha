Manage Subscriptions and RBAC AZ-104

Entra ID tells Azure who you are. Role-based access control (RBAC) decides what you can do, and where. This page covers management groups, scopes, built-in and custom roles, checking access and auditing. Orange tags show the closest AWS equivalent.

Part 1 · Notes

Notes

1. The big idea: scopes and inheritance

Assign once at the top. Everything below inherits it. Permissions only add up, they never shrink going down.

  • Scope levels: management group → subscription → resource group → resource.
  • AWS: Tenant Root Group = Organization root, management group = OU, subscription = account

2. Subscriptions and management groups

  • Subscription: container for resources, and a billing and limits boundary. It trusts one Entra ID tenant.
  • Management group: a folder for subscriptions. Roles and Azure Policy flow down from it.
  • The top group is built in: Tenant Root Group. Up to 6 levels of nesting below it. One subscription sits in one management group at a time. You can move subscriptions between groups.
  • New subscriptions land in the default management group (root unless you change it).
  • To see all subscriptions as a Global Administrator, turn on Access management for Azure resources in Entra ID → Properties. This is called elevating access: you become User Access Administrator at the root.

3. RBAC in one line

WHO: grp-helpdesk-emea+WHAT: VM Contributor+WHERE: mg-contoso-emea=role assignment
  • Who can be a user, group, service principal or managed identity. What is the role definition. Where is the scope. AWS: role definition = IAM policy, assignment = attaching it to a user, group or role
  • Owner: everything, and can give access to others. AWS: like AdministratorAccess
  • Contributor: everything except giving access to others. AWS: like PowerUserAccess
  • Reader: look only. AWS: like ViewOnlyAccess
  • User Access Administrator: only manages who has access.
  • Virtual Machine Contributor: manages VMs, not the OS inside, and not the network or storage they use. Network Contributor manages networks, not access to them.
  • Best practice: assign roles to groups, not individuals. Permissions add up across assignments. Changes can take a few minutes to apply.

4. Real-world examples

  • Europe help desk: VM Contributor on mg-contoso-emea. Covers every EU subscription, including future ones.
  • Finance auditors: Reader on sub-finance-prod.
  • Web developers: Contributor on rg-web-dev only. Network team: Network Contributor on rg-network-hub.
  • Night-shift operators: a custom role that can only start, restart and stop VMs.

5. Custom roles

START: Support Request Contributor−NotActions: register provider=Contoso Support Ticket Agent

Clone a role, remove what you do not want. AWS: customer managed policy

  • Use a custom role when built-in roles give too much or the wrong access (least privilege).
  • A role is JSON: Actions (allowed), NotActions (subtracted), DataActions (data plane, like blob contents), AssignableScopes (where it can be assigned).
  • NotActions is not a deny. If another role grants it, the user still has it. AWS: NotAction behaves the same way, it is not a Deny
  • Ways to create: Portal (clone, start from scratch, or upload JSON), PowerShell, CLI. A real deny comes only from deny assignments (made by Azure Blueprints or managed apps). AWS: explicit Deny or an SCP
Get-AzProviderOperation "Microsoft.Compute/virtualMachines/*" | FT Operation
Get-AzRoleDefinition -Name "Virtual Machine Contributor" | ConvertTo-Json > role.json
New-AzRoleDefinition -InputFile role.json
New-AzRoleAssignment -ObjectId <id> -RoleDefinitionName "Contoso VM Operator" -Scope <scope>

Edit role.json first: new Name, remove Id, set AssignableScopes.

6. Azure roles vs Entra ID roles

  • Azure RBAC roles: control Azure resources, at any scope.
  • Entra ID roles: control the directory (users, groups, apps), at tenant level.
  • Global Administrator does not give Azure resource access until you elevate access.
  • RBAC controls who can do actions. Azure Policy controls what resources may look like. AWS: IAM vs Service Control Policies and Config

7. Checking access and auditing

  • Access control (IAM) → Check access: pick a user or group and see their effective roles at that scope. AWS: IAM policy simulator
  • The Role assignments tab lists who has what, including inherited rows.
  • Activity log: who did what and when, at subscription or management group level. Filter on role assignment operations. AWS: CloudTrail

Good to remember for the exam

  • Role assignment = who + what + where. Roles inherit downward.
  • Owner can assign roles, Contributor cannot. Assign to groups.
  • NotActions is not a deny. Custom roles need AssignableScopes.
  • 6 levels of management groups. One subscription, one group.
  • Azure roles are not Entra ID roles. Elevate access to see all subscriptions.
Part 2 · Exercise

Exercise

Goal: give the Europe help desk limited rights across all EU subscriptions, test Reader and Network Contributor, and audit it. About 50 minutes. Have a security group grp-helpdesk-emea and a test user ready (see the Entra ID page).

1 Mgmt group2 Built-in role3 Reader test4 Custom role5 Check + log

The original labs use az104-mg1, helpdesk and Custom Support Request. Any names work, real-world ones are used here. Reader and Network Contributor steps use standard lab values.

Task 1: Management group

  1. Entra ID → Properties → Access management for Azure resources, so you can manage all subscriptions.
  2. Search Management groups → + Create. ID mg-contoso-emea, display name Contoso EMEA, Submit, refresh.

Check: Contoso EMEA sits under the Tenant Root Group.

Task 2: Built-in role

  1. Open Contoso EMEA → Access control (IAM) → Roles. Open one role to see Permissions, JSON and Assignments.
  2. + Add → Add role assignment → Virtual Machine Contributor → Next → select grp-helpdesk-emea → Review + assign twice.

Check: the group appears on the Role assignments tab. Owners may not notice a change, because Owner already includes it.

Task 3: Reader and Network Contributor at resource group scope

  1. Create a resource group az104-rg-rbac. Open it → IAM → assign Reader to your test user.
  2. Sign in as the test user in a private window. They can see the group but cannot create a resource.
  3. Back as admin, add Network Contributor for the same user. Wait a few minutes, then the test user can create a virtual network in that group, but still no VM.

Task 4: Custom role

  1. IAM → + Add → Add custom role. Name Contoso Support Ticket Agent, clone Support Request Contributor.
  2. Next → + Exclude permissions → search .Support → Microsoft.Support → tick Registers Support Resource Provider → Add. It becomes a NotAction.
  3. Assignable scopes: your management group. Review the JSON, Create.
  4. Optional: in Cloud Shell run the PowerShell block from the notes to make a VM-operator role from JSON.

Task 5: Check access and Activity log

  1. IAM → Check access → pick the test user and group to see effective roles.
  2. Open Activity log, filter to role assignment operations, find your changes.

Clean up: delete az104-rg-rbac, the test role and the management group.

Part 3 · Test yourself

Test yourself

Try each question first. Press the button to show every answer under its question.

Check answersHide answers
  1. What three things make up a role assignment?
    Who (user, group or app), what (the role), and where (the scope).
  2. The Europe help desk needs the same access on 12 EU subscriptions and any new ones. Where do you assign the role?
    On the management group holding the EU subscriptions. Every subscription inherits it, including new ones.
  3. Name the four scope levels from top to bottom.
    Management group, subscription, resource group, resource.
  4. What can Owner do that Contributor cannot?
    Give access to others (create role assignments).
  5. Which role only manages who has access, nothing else?
    User Access Administrator.
  6. Which is NOT allowed by Virtual Machine Contributor?
    1. Start and stop VMs
    2. Create a VM
    3. Log in to the operating system
    4. Resize a VM
    C. It manages VMs, not the OS inside, nor the network or storage they use.
  7. Is a permission in NotActions denied for the user?
    No. It is only subtracted from that role's Actions. Another role can still grant it.
  8. What creates a real deny in Azure RBAC?
    A deny assignment (made by Azure Blueprints or managed applications). Custom roles cannot deny.
  9. Why assign roles to groups, not people?
    Easier to manage: change group membership instead of many role assignments.
  10. Azure RBAC roles vs Entra ID roles: what is the difference?
    RBAC roles control Azure resources at many scopes. Entra roles control the directory (users, groups, apps) at tenant level.
  11. You are Global Administrator but see no subscriptions. Why, and what is the fix?
    Entra roles give no Azure resource access. Turn on Access management for Azure resources to become User Access Administrator at the root.
  12. Who gave a contractor access to production last Tuesday? Where do you look?
    The Activity log of that subscription or management group, filtered on role assignment operations.
  13. A contractor must only start, restart and stop VMs in rg-web-weu. What do you do?
    Create a custom role with just those VM actions plus read, and assign it at the resource group scope.
  14. A user has Reader at the subscription and Contributor on one resource group. What can they do in that group?
    Everything Contributor allows there. Permissions add up, nothing from Reader takes it away.
  15. How many levels of management groups can you nest below the root, and how many groups can a subscription be in?
    Six levels. A subscription belongs to one management group at a time.
  16. Where does a new subscription go by default?
    Into the default management group, which is the Tenant Root Group unless you change it.
  17. What do AssignableScopes control in a custom role?
    Where the role can be assigned, such as a management group, subscription or resource group.
  18. What is the difference between Actions and DataActions?
    Actions cover management operations. DataActions cover the data inside resources, such as reading blob contents.
  19. Which PowerShell cmdlet creates a custom role from a JSON file?
    New-AzRoleDefinition -InputFile role.json. Remember to change the Name and remove the Id first.
  20. How do you see what effective access a user has on a scope?
    IAM → Check access, and the Role assignments tab which also shows inherited rows.
  21. You just assigned a role and the user still gets Access denied. What is likely?
    Propagation delay. Wait a few minutes and have the user sign out and in again.
  22. What is the AWS equivalent of a management group and of a subscription?
    OU in AWS Organizations, and an AWS account.
  23. What does RBAC control versus Azure Policy?
    RBAC controls who can act. Azure Policy controls what resources may look like and where they can be created.
  24. Which role fits a team that must manage virtual networks but not give others access?
    Network Contributor.
  25. Auditors must see everything in the finance subscription but change nothing. Which role and scope?
    Reader at the subscription scope.
  26. When would you choose a custom role over a built-in one?
    When built-in roles give too much or the wrong access, to follow least privilege.
