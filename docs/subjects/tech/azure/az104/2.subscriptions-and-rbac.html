Manage Subscriptions and RBAC AZ-104

Entra ID tells Azure who you are. Role-based access control (RBAC) decides what you can do, and where.

Part 1

Notes

The big idea: scopes and inheritance

Subscriptions and management groups

  • Subscription: a container for resources. It is a billing and limits boundary.
  • Each subscription trusts one Entra ID tenant.
  • Management group: a folder for subscriptions. Roles and Azure Policy flow down from it.
  • The top one is built in: Tenant Root Group. You can nest up to 6 levels below it.
  • A subscription sits in one management group at a time.
  • To see all subscriptions as a Global Administrator, turn on Access management for Azure resources in Entra ID → Properties.

RBAC in one line

  • Owner: everything, plus can give access to others.
  • Contributor: everything except giving access to others.
  • Reader: look only.
  • User Access Administrator: only manages who has access.
  • Virtual Machine Contributor: manages VMs, but not the OS inside, and not the network or storage they use.
  • Best practice: assign roles to groups, not to individuals.

Real-world examples

  • Contoso Europe help desk: VM Contributor on mg-contoso-emea. Covers every EU subscription, including new ones added later.
  • Finance auditors: Reader on sub-finance-prod. They can look, never change.
  • Web developers: Contributor on rg-web-dev only. No access to production.
  • Network team: Network Contributor on rg-network-hub.
  • Outsourced night-shift operators: a custom role that can only start, restart and stop VMs.

Custom roles

  • Use a custom role when built-in roles give too much (or the wrong) access.
  • A role is a JSON file: Actions (allowed), NotActions (taken away), AssignableScopes (where it can be used). Data operations use DataActions.
  • NotActions is not a deny. It only subtracts from Actions. Another role can still grant the same permission.
{
  "Name": "Contoso Support Ticket Agent",
  "Actions": [ "Microsoft.Support/*", ... ],          // simplified
  "NotActions": [ "Microsoft.Support/register/action" ],
  "AssignableScopes": [ "/providers/Microsoft.Management/managementGroups/mg-contoso-emea" ]
}

Azure roles vs Entra ID roles

  • Azure RBAC roles: control Azure resources (VMs, storage). Work at any scope level.
  • Entra ID roles: control the directory (users, groups, apps). Work at tenant level.
  • Being Global Administrator does not give access to Azure resources by default.

Activity log

  • Records who did what, and when, at subscription and management group level.
  • Filter by operation (for example role assignments) to audit access changes.
Part 2

Exercise

Goal: give the Europe help desk limited rights across all EU subscriptions. About 30 minutes. Before you start, have a security group for the help desk (create grp-helpdesk-emea as in the previous topic if needed).

The original steps use the names az104-mg1, helpdesk and Custom Support Request. Any names work. Real-world names are used here.

Task 1: Management group

  1. Microsoft Entra ID → Properties. Under Access management for Azure resources, check you can manage all subscriptions and management groups.
  2. Search Management groups → + Create.
    • ID: mg-contoso-emea (must be unique in the directory)
    • Display name: Contoso EMEA
    • Submit, then refresh (can take a minute)
  3. Spot the Tenant Root Group. In real life you would now move the EU subscriptions into this group.

Check: Contoso EMEA is listed under the Tenant Root Group.

Task 2: Assign a built-in role

  1. Open Contoso EMEA → Access control (IAM) → Roles tab. Browse the roles. Open one to see Permissions, JSON and Assignments.
  2. + Add → Add role assignment → pick Virtual Machine Contributor → Next.
  3. Select members → grp-helpdesk-emea → Select.
  4. Review + assign (twice).

Check: on the Role assignments tab the group has Virtual Machine Contributor. (If you are an Owner, you may not notice a change. Owner already includes it.)

Task 3: Create a custom role

  1. Same IAM page: + Add → Add custom role.
  2. Basics tab:
    • Name: Contoso Support Ticket Agent
    • Description: Create and manage support tickets. Cannot register resource providers.
    • Baseline permissions: Clone a role → Support Request Contributor
  3. Next → + Exclude permissions → search .Support → pick Microsoft.Support.
  4. Tick Other: Registers Support Resource Provider → Add. It becomes a NotAction.
  5. Assignable scopes: make sure your management group is listed. Review the JSON.
  6. Review + Create → Create.

Check: the new role shows in the IAM Roles tab as a CustomRole. To use it, assign it to the group the same way as Task 2.

Task 4: Activity log

  1. Open Contoso EMEA → Activity log.
  2. Filter the operation to role assignments and find the one you made.

Cleanup: delete the management group and test role when you are done. This stops clutter, and keeps your own subscription tidy.

Good to remember for the exam

  • Role assignment = who + what + where.
  • Assigned roles inherit downward: management group > subscription > resource group > resource.
  • Owner can assign roles. Contributor cannot.
  • Assign to groups, not individuals.
  • NotActions subtracts permissions. It is not a deny.
  • Custom roles need AssignableScopes.
  • Management groups: up to 6 levels deep. One subscription belongs to one group.
  • Azure RBAC roles are not the same as Entra ID roles.
Part 3

Test yourself

Think first, then press Show answer under each question.

  1. What three things make up a role assignment?
    Show answer
    Who (user, group or app), what (the role), and where (the scope).
  2. The Contoso Europe help desk needs the same access on 12 EU subscriptions, and on any new ones. Where do you assign the role?
    Show answer
    On the management group that holds the EU subscriptions. Access is inherited by every subscription in it, including new ones.
  3. What can Owner do that Contributor cannot?
    Show answer
    Give access to others (create role assignments). Contributor can manage resources but cannot assign roles.
  4. Which is NOT allowed by Virtual Machine Contributor?
    1. Start and stop VMs
    2. Create a VM
    3. Log in to the operating system
    4. Resize a VM
    Show answer
    C. The role manages VMs but not the OS inside them, and not the virtual network or storage they use.
  5. Is a permission listed in NotActions denied for the user?
    Show answer
    No. NotActions just removes it from that role's Actions. If another role grants the same permission, the user still has it.
  6. Why assign roles to groups instead of people?
    Show answer
    Easier to manage. When someone joins or leaves, you change group membership and not dozens of role assignments.
  7. What is the difference between Azure RBAC roles and Entra ID roles?
    Show answer
    Azure RBAC roles control Azure resources and work at many scopes. Entra ID roles control the directory (users, groups, apps) at tenant level.
  8. Your security team asks who gave a contractor access to the production subscription last Tuesday. Where do you look?
    Show answer
    The Activity log of that subscription (or management group). Filter on role assignment operations.
  9. A contractor must only start, restart and stop VMs in rg-web-weu. What do you do?
    Show answer
    Create a custom role with just the VM start, restart, deallocate and read actions. Assign it to the contractor (or their group) at the resource group scope.
  10. You are a Global Administrator but cannot see any subscriptions in the portal. Why, and what is the fix?
    Show answer
    Entra ID roles do not give Azure resource access. Turn on Access management for Azure resources in Entra ID Properties to elevate yourself to User Access Administrator at the root.
