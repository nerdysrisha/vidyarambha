Building Virtual Machines AZ-104

An Azure VM is never just "a server". It is a virtual machine plus a small set of networking and storage resources that sit around it: a virtual network to live in, a network card to connect, disks to boot from, and rules to decide what traffic gets in.

The picture

The pieces

PieceWhat it does
Resource groupThe folder that holds everything for the VM, so it can be managed, tagged and deleted together.
Virtual network (VNet)The private network space the VM lives in, for example 172.16.0.0/16.
SubnetA slice of the VNet, for example 172.16.0.0/24. The VM's network card is attached to one subnet.
Network interface (NIC)The VM's network card. It carries the IP configuration and is bound to the subnet.
Private IPThe internal address inside the VNet, such as 172.16.0.4. It is handed out from the subnet range.
Public IPOptional. A separate resource that lets the Internet reach the VM. It is linked through the NIC's IP configuration.
Network security group (NSG)A list of allow/deny rules for traffic. It can be attached to the subnet, to the NIC, or both.
OS diskThe disk the operating system boots from. Extra data disks are optional.

Good to remember for the exam

  • A VM needs at least one NIC, and each NIC sits in exactly one subnet. The VM, NIC and VNet must be in the same region.
  • Azure reserves the first four addresses and the last one in every subnet, which is why the first VM in 172.16.0.0/24 gets 172.16.0.4.
  • NSG rules can apply at the subnet level, the NIC level, or both. When both exist, traffic must be allowed by each of them.
  • A public IP is optional. A VM with no public IP can still reach and be reached by other resources inside the VNet.
