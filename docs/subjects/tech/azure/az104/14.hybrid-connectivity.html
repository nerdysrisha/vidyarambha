Hybrid Connectivity: VPN, ExpressRoute and Virtual WAN AZ-104

How an on-premises network connects to Azure. You build the Azure side of a VPN (VNet, GatewaySubnet, VPN gateway) and learn when to choose Site-to-Site, Point-to-Site, ExpressRoute or Virtual WAN.

The gateway is the Azure end of the connection.

Key ideas

  • Site-to-Site (S2S): connects a whole office network to a VNet through an IPsec tunnel over the Internet. Needs a VPN device on-premises with a public IP.
  • Point-to-Site (P2S): connects a single computer to a VNet. Good for remote workers.
  • ExpressRoute: a private connection through a provider that does not use the public Internet. More predictable and faster, but costs more.
  • Virtual WAN: a managed hub for connecting many branches, users and VNets at large scale.
  • The VPN gateway needs a GatewaySubnet, a public IP, and a VPN type (route-based is the usual choice).
  • Address spaces on-premises and in Azure must not overlap.

Exam box

  • Whole office → S2S. One laptop → P2S. Private, not over Internet → ExpressRoute.
  • Gateway subnet name must be exactly GatewaySubnet.
  • A gateway takes about 30 to 45 minutes to deploy.
Part 2

Exercise

Goal: build the Azure side of a VPN: VNet, GatewaySubnet and VPN gateway, then inspect connection options. About 20 minutes of work plus gateway wait time.

Cost warning: a VPN gateway bills while it exists. Delete the resource group when done. Names are standard lab-style values: az104-rg15, az104-vnet15, az104-vpngw15.

Task 1: Virtual network

  1. Create a resource group az104-rg15.
  2. Create a VNet az104-vnet15 with address space 10.15.0.0/16 and a subnet 10.15.1.0/24.
  3. Open the VNet → Subnets → + Gateway subnet. Accept the name GatewaySubnet and a /27 range.

Task 2: VPN gateway

  1. Search Virtual network gateways → Create.
  2. Name az104-vpngw15, gateway type VPN, VPN type Route-based, select the VNet, create a new public IP.
  3. Select Review + create, Create, and wait for deployment.

Task 3: Inspect

  1. Open the gateway → Connections and Point-to-site configuration. Note where S2S and P2S are set up.
  2. Search ExpressRoute circuits and Virtual WANs and read the create forms without creating.

Check: the gateway shows Succeeded and the subnet is named GatewaySubnet.

Clean up: delete az104-rg15.

Check answersHide answers
  1. Connect a whole branch office to a VNet over the Internet. Which option?
    Site-to-Site VPN.
  2. Connect one remote laptop to a VNet. Which option?
    Point-to-Site VPN.
  3. Why choose ExpressRoute over a VPN?
    It is a private connection that does not cross the public Internet, with more predictable performance.
  4. What must the gateway subnet be named?
    GatewaySubnet, exactly.
  5. What is Virtual WAN for?
    A managed hub that connects many branches, users and VNets at large scale.
  6. Your on-premises network is 10.0.0.0/16 and the VNet is also 10.0.0.0/16. What is the problem?
    Overlapping address spaces. Routing cannot work, so one side must be changed.
  7. What does the on-premises side need for Site-to-Site?
    A VPN device with a public IP address.
  8. The gateway deployment is still running after 10 minutes. Is something wrong?
    No. A VPN gateway normally takes 30 to 45 minutes.
