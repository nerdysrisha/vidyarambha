Data Protection: Azure Backup and Site Recovery AZ-104

Backup brings your data back after it is deleted or damaged. Site Recovery keeps a copy of a whole VM running in another region, so you can switch over after a disaster. Both use a Recovery Services vault. This topic covers vaults, backup policies, soft delete, monitoring and VM replication.

Backup vs Site Recovery

  • Azure Backup = take copies (recovery points) on a schedule and restore data or a VM later. Protects against accidental or malicious deletion and corruption.
  • Azure Site Recovery (ASR) = keep a copy of the VM running in a second region and fail over if the first region has an outage. This is disaster recovery.
  • Backup is for getting data back. ASR is for getting the whole workload running again quickly with little downtime.
  • Backup works for Azure VMs, on-premises servers, SQL Server in VMs, Azure file shares and more.

Recovery Services vault

  • A Recovery Services vault is the storage and management container for backup data and ASR replication.
  • For backup, the vault must be in the same region as the VM. For ASR, the vault goes in the target (different) region.
  • Storage replication type: Locally-redundant, Zone-redundant or Geo-redundant (default). It can only be changed when the vault has no backup items.
  • Cross Region Restore lets you restore into the paired region. It needs geo-redundant storage.
  • Azure has two vault types: Recovery Services vault (VMs, files, SQL, ASR) and Backup vault (other data sources, such as blobs and disks).
  • Soft delete keeps deleted backup data for a while (the lab shows 14 days), so a deleted backup can be recovered.

Backup policy

Policyaz104-backupStandard, daily 12:00 AM
instant snapshot: 2 daysvault retention

The policy answers: how often, at what time, and how long to keep each recovery point.

  • A policy sets frequency, time, time zone and retention. Different VMs can use different policies.
  • Policy sub types: Standard (one backup per day) and Enhanced (more than one backup per day, plus support for newer VM types such as Trusted launch).
  • Instant recovery snapshots are kept next to the VM disks, so restores are fast. Standard allows 1 to 5 days (default 2).
  • Older recovery points are kept in the vault for the retention period you set.
  • Backup now runs an on-demand backup. The Retain Backup Till date has a default you can accept.
  • Enabling backup installs a backup extension on the VM. Backup Pre-Check and Last Backup Status show health.

Monitoring Azure Backup

  • Monitoring → Backup jobs lists backup operations. Use View details for one job.
  • Diagnostic settings send vault logs and metrics to a destination: Log Analytics workspace, storage account (archive), Event Hub or a partner solution.
  • The lab sends these categories: Backup Reporting Data, Backup Job Data, Backup Alert Data, Site Recovery Jobs and Site Recovery Events.

Site Recovery: replicating a VM

VM disks→ replicate →replica disks
test failoverfailoverfailback

Replication runs all the time. You only start the replica when you fail over or test.

  • On the VM: Backup + Disaster recovery → Disaster recovery. Pick the target region (must differ from the VM's region).
  • The wizard fills in target resources, and creates an automation account (it manages the agent updates). If the settings are not filled in, validation fails.
  • The first copy takes time (10 to 15 minutes in the lab). Status starts at 0% synchronization, then becomes Protected.
  • Check it in the target vault: Protected items → Replicated items. Replication health should be healthy.
  • Good practice: run a test failover (a drill) without affecting production.
Part 2

Exercise

Goal: deploy a VM from a template, back it up with a policy, send vault logs to storage, then replicate the VM to another region. About 50 minutes.

1 Template2 Vault3 VM backup4 Monitor5 Replicate

Lab names are kept: az104-rg-region1, az104-rsv-region1, az104-rg-region2, az104-rsv-region2. Regions are East US and West US. The lab writes the VM name as both az104-10-vm0 and az-104-10-vm0. Use the name you see in the portal.

Task 1: Use a template to provision an infrastructure

  1. Download the \Allfiles\Lab10\ lab files. Sign in to the Azure portal.
  2. Search for and select Deploy a custom template → Build your own template in the editor.
  3. Load file: az104-10-vms-edge-template.json, then Save. (It deploys a virtual network and a VM.)
  4. Edit parameters → Load file: az104-10-vms-edge-parameters.json, then Save.
  5. Fill in the form:
    • Resource group az104-rg-region1 (create new if needed), Region East US
    • VM size Standard_D2s_v5 if available
    • Username localadmin, and a complex password
  6. Review + Create, then Create. Wait, then Go to resource.

If the size is unavailable or capacity is short, redeploy to the same group with Standard_D2s_v6, then Standard_D2s_v7. If a retry fails because of a conflicting partial deployment, delete az104-rg-region1 and restart Task 1.

Check: the resource group has one virtual machine in one virtual network.

Task 2: Create and configure a Recovery Services vault

  1. Search for Recovery Services vaults → + Create.
  2. Resource group az104-rg-region1, Vault name az104-rsv-region1, Region East US (same region as the VM).
  3. Review + Create, then Create. Then Go to Resource.
  4. Settings → Properties → Update under Backup Configuration. Review Storage replication type, keep Geo-redundant, close.
  5. Under Security Settings → Soft Delete Settings, select Update. Confirm retention is 14 days, close.

Check: the vault exists, is geo-redundant, and soft delete retention shows 14 days.

Task 3: Configure Azure virtual machine-level backup

  1. On the vault: Overview → + Backup. Workload runs in Azure, back up Virtual machine, then Backup.
  2. Policy sub type: choose Standard. Select Create a new policy.
  3. Policy name az104-backup, Frequency Daily, Time 12:00 AM, your time zone, instant recovery snapshots 2 days. OK.
  4. Under Virtual Machines select Add, tick the lab VM, OK, then Enable backup (about 2 minutes). Go to resource.
  5. Protected items → Backup items → Azure virtual machine → View details. Look at Backup Pre-Check and Last Backup Status (pending).
  6. Select Backup now, accept the default Retain Backup Till, OK. Do not wait for it to finish.

Check: the VM is listed under Backup items, and an on-demand backup job has started.

Task 4: Monitor Azure Backup

  1. Create a storage account: group az104-rg-region1, a globally unique name, Region East US. Create.
  2. Open the vault → Monitoring → Diagnostic Settings → Add diagnostic setting.
  3. Name Logs and Metrics to storage. Tick Azure Backup Reporting Data, Addon Azure Backup Job Data, Addon Azure Backup Alert Data, Azure Site Recovery Jobs and Azure Site Recovery Events.
  4. Destination: Archive to a storage account, pick your account, Save.
  5. Back on the vault: Monitoring → Backup jobs. Find the VM's job and open View details (scroll right).

Check: the diagnostic setting is saved, and you can see the VM's backup job and its details.

Task 5: Enable virtual machine replication

  1. Create a second vault: group az104-rg-region2 (new), name az104-rsv-region2, Region West US (different from the VM). Create.
  2. Open the VM → Backup + Disaster recovery → Disaster recovery. On Basics, note the Target region.
  3. Next: Advanced settings. The selections are filled in. Scroll down and Create the automation account. The settings must be populated or validation fails.
  4. Review + Start replication, then Start replication. It takes 10 to 15 minutes.
  5. Open az104-rsv-region2 (refresh if needed) → Protected items → Replicated items.
  6. Check the replication health is healthy. Status starts at 0% and ends as Protected. Select the VM for details.

Check: the VM appears under Replicated items with healthy replication and, after the first sync, status Protected.

Cleanup: delete az104-rg-region1 and az104-rg-region2 (select the group, Delete the resource group, type its name, Delete, confirm again). CLI: az group delete --name az104-rg-region1. A vault with protected items will not delete until you stop protection, remove the items and turn off soft delete first.

Good to remember for the exam

  • Backup = restore data. Site Recovery = run the workload in another region (failover). Both live in a Recovery Services vault.
  • For backup the vault must be in the same region as the VM. For ASR the vault is in the target region.
  • Storage redundancy: LRS, ZRS or GRS (default). Change it only before any backup items exist. Cross Region Restore needs GRS.
  • Policy = frequency, time, time zone, retention. Standard = one backup per day. Enhanced = several per day.
  • Instant restore snapshots: 1 to 5 days on Standard (default 2), for fast restores.
  • Soft delete (14 days in the lab) protects against deleted backups. Disable it and remove items before deleting a vault.
  • Backup now = on-demand backup. Backup jobs shows status.
  • Diagnostic settings can send vault logs to Log Analytics, a storage account, Event Hub or a partner.
  • Recovery Services vault covers VMs, files and SQL. Backup vault covers other data sources.
  • Test failover (a drill) does not touch production. Replication status ends as Protected.

  1. What is the main difference between Azure Backup and Azure Site Recovery?
    Backup takes recovery points so you can restore data or a VM after loss or damage. Site Recovery replicates a VM to another region so you can fail over and keep running after a disaster.
  2. What is a Recovery Services vault?
    A storage and management container for backup data and Site Recovery replication. It reduces management work.
  3. You back up a VM in East US. Where must the Recovery Services vault be?
    1. Any region
    2. East US, the same region as the VM
    3. West US only
    4. Same region as the storage account
    B. For VM backup the vault must be in the same region as the VM. (For Site Recovery, the vault is in the target region.)
  4. The vault storage replication type is geo-redundant. When can you change it?
    Only when the vault has no existing backup items.
  5. Which setting lets you restore data in the paired region?
    1. Soft delete
    2. Cross Region Restore
    3. Instant restore snapshots
    4. Backup now
    B. Cross Region Restore restores data into the secondary, paired region. It needs geo-redundant storage.
  6. What does soft delete do, and what is the retention shown in the lab?
    It keeps deleted backup data so it can be recovered. The lab shows 14 days.
  7. What does a backup policy define?
    How often to back up (frequency), at what time and time zone, and how long to keep recovery points. Different VMs can use different policies.
  8. You need more than one backup per day for a VM. Which policy sub type?
    1. Standard
    2. Enhanced
    3. Basic
    4. Archive
    B. Enhanced supports multiple backups per day. Standard gives one per day.
  9. What are instant recovery snapshots good for?
    Fast restores, because the snapshot is kept close to the VM disks. The lab keeps them for 2 days.
  10. You want vault logs kept for later analysis in a storage account. What do you configure?
    A diagnostic setting on the vault. Pick the log categories, then choose Archive to a storage account as the destination. Other options are Log Analytics, Event Hub and partner solutions.
  11. Where do you check on-demand and scheduled backup operations?
    On the vault under Monitoring → Backup jobs. Use View details for one job.
  12. How do you know the VM replication has finished and is working?
    In the target-region vault, under Protected items → Replicated items: health is healthy and the status moves from 0% synchronization to Protected.
