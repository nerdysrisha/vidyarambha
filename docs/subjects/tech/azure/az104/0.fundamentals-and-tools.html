Azure Fundamentals and Tools AZ-104

The base ideas every other topic uses: how Azure is organized, how you talk to it, and how deployments are repeated with code. You create the same resource group with the Portal, CLI and PowerShell, then look at a template.

Every tool sends the same request to ARM, so they all give the same result.

Key ideas

  • Hierarchy: management group → subscription → resource group → resource. A resource lives in exactly one resource group.
  • Region is a geographic area. An availability zone is a separate datacenter inside a region, used for resilience.
  • IaaS: you manage the OS and up (VM). PaaS: Azure manages the OS, you manage the app (App Service).
  • Infrastructure as Code: describe resources in a file (ARM JSON or Bicep) and deploy it repeatedly with the same result.
  • Cloud Shell is a browser shell with CLI and PowerShell already signed in. It needs a storage account to keep files.

Exam box

  • CLI is az ..., PowerShell is Get-Az... / New-Az....
  • Deleting a resource group deletes everything inside it.
  • Bicep compiles to an ARM template. Both are declarative and idempotent.
Part 2

Exercise

Goal: create the same resource group with the Portal, CLI and PowerShell, then deploy a template. About 25 minutes.

Names used: az104-rg14, az104-rg14-cli, az104-rg14-ps. These are standard lab-style values, change them if you like.

Task 1: Portal

  1. Search Resource groups → Create. Name az104-rg14, a region of your choice, Review + create, Create.
  2. Open it and note the subscription, location and the Activity log.

Task 2: Cloud Shell

  1. Select the Cloud Shell icon in the top bar. Choose Bash and create the storage if asked.
  2. Run: az group create -n az104-rg14-cli -l eastus
  3. Switch to PowerShell and run: New-AzResourceGroup -Name az104-rg14-ps -Location eastus
  4. List them: az group list -o table

Task 3: Deploy a template

  1. In the portal create a Storage account in az104-rg14 (do not finish), and on Review + create select Download a template for automation.
  2. Review the resources and parameters sections. Note it is JSON and declarative.
  3. Finish creating the account, then open the resource group → Export template to see the same idea for existing resources.

Check: all three resource groups exist, and you can say which tool you used for each.

Clean up: az group delete -n az104-rg14-cli --yes and delete the other two groups.

Part 3

Test yourself

Try each question first. Press the button to show every answer under its question.

Check answersHide answers
  1. Which scope holds resources, and can a resource be in two of them?
    The resource group. A resource belongs to exactly one resource group.
  2. What is Azure Resource Manager?
    The deployment and management layer. The Portal, CLI, PowerShell and templates all call it, so they behave the same.
  3. IaaS or PaaS: a web app where Azure patches the OS?
    PaaS (App Service). With a VM (IaaS) you patch the OS yourself.
  4. What is the difference between a region and an availability zone?
    A region is a geographic area. An availability zone is a physically separate datacenter inside a region.
  5. What does declarative mean for an ARM template or Bicep file?
    You describe the end state, not the steps. Redeploying the same file gives the same result.
  6. What happens when you delete a resource group?
    Every resource inside it is deleted too.
  7. What does Cloud Shell need to keep your files?
    A storage account (an Azure Files share) mounted to the shell.
  8. Which command creates a resource group in PowerShell?
    New-AzResourceGroup. The CLI equivalent is az group create.
