①
User runs: oc exec -it helloworld -- curl http://cdh:8006/cdh/resource/default/kbsres1/key1 helloworld pod → CDH inside Peer Pod VSI
▶
① helloworld pod calls CDH :8006 — secret request
②
CDH receives the resource request. CDH cannot return the secret yet — it must prove the workload is running in a genuine TDX environment. CDH internally calls the Attestation Agent (AA) to start attestation. CDH → AA (internal call inside Peer Pod VSI)
③
AA asks TDX CPU to generate a signed hardware quote. The CPU reads MRTD (TD measurement) and RTMR[0–3] (runtime measurements) from its secure registers and signs them with the Intel platform key (PCK). AA → TDX CPU hardware (local call inside VSI)
TDX quote contains:
· MRTD — measurement of the TD itself
· RTMR[0–3] — firmware, kernel, workload
· PCK certificate chain (embedded)
· Hardware signature (unforgeable)
④
TDX CPU returns the signed quote back to AA. AA now has evidence it is running on genuine Intel TDX hardware. TDX CPU → AA (local, inside Peer Pod VSI)
⑤
AA sends the TDX quote over the VPC network to KBS on Trustee VSI. This crosses the VPC subnet boundary but stays within IBM Cloud — no public internet. AA → KBS :8080 (VPC private IP, no internet)
▶
⑤ AA sends signed TDX quote → KBS :8080 (VPC private, no internet)
⑥
KBS receives the quote from AA. KBS does not verify quotes itself — it delegates verification to AS. KBS calls AS over internal gRPC on port 50004 (docker-compose internal network, not exposed outside VSI). KBS → AS :50004 (docker-compose internal network)
⑦
AS receives the quote and calls its internal DCAP libraries to verify it. The DCAP library (libsgx-dcap-quote-verify) uses the QPL library (libsgx-dcap-default-qpl) to fetch certificate collateral needed to validate the quote signature. AS internally calls DCAP C library (inside trustee-as-1 container)
DCAP library reads: /etc/sgx_default_qcnl.conf
collateral_service → Intel PCS URL
local_cache_only: false
tcb_update_type: early
⑧
QPL (inside trustee-as-1 container) makes the internet call to Intel PCS. This is the only internet-bound call in the entire flow. QPL fetches the PCK certificate chain and TCB info needed to verify the quote signature. QPL library inside trustee-as-1 → Intel PCS (PUBLIC INTERNET)

▶
⑧ QPL (inside trustee-as-1) → Intel PCS — INTERNET CALL
◀
⑨ PCK cert chain + TCB collateral returned to QPL
⑨
QPL returns cert collateral to AS. AS now uses libsgx-dcap-quote-verify to cryptographically verify the TDX quote signature against the PCK certificate chain from Intel. If valid, the quote is genuine TDX hardware evidence. All inside trustee-as-1 container — no network call
⑩
AS calls RVPS to check whether the measurements in the quote (MRTD, RTMR values) match expected/trusted values. RVPS compares against pre-registered reference values. AS → RVPS :50003 (docker-compose internal network)
POC state: no reference values registered
→ RVPS running in allow-all mode
measurements accepted regardless of value
Production: register expected MRTD /
RTMR values via kbs-client set-resource
⑪
RVPS returns OK to AS. AS generates a signed JWT attestation token (signed with token.key). AS returns this token to KBS. RVPS → AS → KBS (docker-compose internal)
⑫
KBS validates the JWT token from AS. Both checks passed (quote valid + measurements OK). KBS looks up the requested secret (default/kbsres1/key1) from its local storage and releases it back to AA. KBS → AA :8080 response (VPC private IP, no internet)
Secret released: res1val1
Stored at: kbs-storage/default/kbsres1/key1
Registered via: kbs-client set-resource
◀
⑫ secret "res1val1" → AA → CDH → pod curl response
⑬
CDH passes secret to the pod. Pod's curl call returns with the secret value. CDH → helloworld pod — curl response
curl output: res1val1 ✓
⑬
AA receives secret from KBS. AA passes it to CDH. CDH returns it as the HTTP response to the original curl from the pod. KBS → AA → CDH → pod (all inside Peer Pod VSI + VPC)
