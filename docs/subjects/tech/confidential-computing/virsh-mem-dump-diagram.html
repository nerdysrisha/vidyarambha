▼ FORK · two ways an admin can try to read guest RAM: ⑦ ⑧ dump to a file, then decipher offline · ⑨ ⑩ live peek, no file and no pause
⑦
Dump path. suspend → dump --memory-only --format elf --bypass-cache → sha256sum → resume. virsh → libvirtd → QEMU → file on host
Customer-visible: the VSI is paused for the whole dump. --live avoids the pause but smears the image.

⑧
Decipher offline. Open the ELF in Volatility 3, crash, strings or YARA to rebuild processes, connections and secrets. analysis on the dump file
✗ CLEARTEXT. Full RAM image: disk-encryption keys, TLS private and session keys, DB buffers, credentials, process list and network table.
✓ NO PLAINTEXT. Private pages are encrypted by the CPU with a key the host never holds. The dump yields ciphertext, zeros or an error, so there is nothing to decipher.
⑨
Live peek path. virsh qemu-monitor-command --hmp 'xp /64xb <addr>' · pmemsave · read the QEMU process memory · introspection tools (LibVMI). No file, no pause. host root → running QEMU process
Bypasses libvirt access control: monitor passthrough is an unsupported low-level path and skips polkit rules.

⑩
Decipher live. Raw bytes are easy to read. Turning them into processes, keys and sessions needs a profile (LibVMI or Volatility), and can be repeated to watch memory change. introspection tooling on the host
✗ LIVE CLEARTEXT. Real-time view; polling can catch keys while they are in use. The VSI is never paused, so the customer sees no outage and no alert.
✓ NO PLAINTEXT. Reads return ciphertext, or fault or error. Nothing to interpret.
Caveat: shared pages (I/O bounce buffers) stay host-visible. They are not the guest's private memory.
